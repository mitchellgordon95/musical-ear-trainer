# Musical Ear Trainer

Ear trainer built on real recordings: short slices of songs you know, and you find the tonic, name the scale degrees, or name the song from its degrees. Live at **https://ear-trainer.mitchgordon.me**. MIT licensed (`LICENSE`).

Static single-page app plus the data pipeline that feeds it. No build step, no framework. This public repo is a snapshot mirror of the `code/` directory of a private repo that also holds the project's notes; each commit here is one sync. Issues and PRs are welcome and get applied upstream by hand.

## Data

The app's data is **not in this repo**: `public/clips.json`, `public/lyrics/`, `data/raw/` and `data/clips_full.json` are Hooktheory Theorytab transcriptions and song lyrics, which stay with their owners, and `data/spotify_*` is one person's listening history. All of it is regenerated by the pipeline below from `scripts/songs.txt` (`fetch_theorytab.py` → `fetch_lyrics.py` → `mine_moments.py`; about 2 s per Theorytab section). `data/prominence.json` *is* included so you don't need the 1 GB audio pass to get a working `clips.json`.

## Layout

- `public/index.html` — the whole app, hooks only (2026-10-02): an endless session (no rounds; least-recently-asked hook next) of three exercises — find the tonic on a 12-key keyboard over a longer clip, name every scale degree of the hook over a tonic drone, name the song from its degrees; starting tone on the synth; the clip and lyrics play on reveal (the clip runs on past the hook by a chosen number of chords, or to the end of the section, from the Theorytab chord track); 👍/👎 per hook; anchors-per-interval table; song checklist. Vanilla JS, YouTube IFrame API for playback, WebAudio for the tone. Settings and hook ratings live in `localStorage`. The v0 two-note recognition Drill and Browse tabs were removed in the same commit (git has them); the pipeline still emits `clips` for them.
- `public/clips.json` — generated, what the app loads. `sections` (per Theorytab section: song, key, bpm, YouTube id, timing flag, notes, chord onsets) and `hooks` (melodic phrases of 3–8 notes cut at rests ≥ 1 beat, with per-note Theorytab scale degrees, the key and tonic at the hook, the interval sequence and first interval/degree; phrase 0 of each Chorus is the default pool). `data/clips_full.json` additionally holds the two-note `clips` (interval moments with clarity score) that `verify_clips.py` scores.
- `scripts/fetch_theorytab.py` — Theorytab page (via r.jina.ai) → Hookpad section ids → `api.hooktheory.com/v1/songs/public/<id>` → `data/raw/*.json`; also caches YouTube video lengths in `data/videos.json`.
- `scripts/mine_moments.py` — `data/raw/*.json` → `public/clips.json`. Pitch and timing math are documented in [../docs/data-pipeline.md](../docs/data-pipeline.md).
- `scripts/fetch_lyrics.py` — manual YouTube caption tracks via `yt-dlp`, else lrclib when the video length matches the studio track → `public/lyrics/<ytid>.json`.
- `scripts/verify_clips.py` — melody prominence from the audio (see [../docs/data-pipeline.md](../docs/data-pipeline.md)) → `data/prominence.json`, merged by `mine_moments.py`.
- `scripts/songs.txt` — Theorytab slugs to fetch (`artist/song`), one per line.
- `scripts/spotify_top.py` — Mitchell's most-played Spotify tracks (Web API, `GET /me/top/tracks`, PKCE sign-in, stdlib only) → `data/spotify_top.json`; `--playlists` every playlist with its tracks (`GET /playlists/{id}/items`; the old `/tracks` path 403s since 2026-02; other people's playlists are no longer readable) → `data/spotify_playlists.json`; `--propose` checks each track (top tracks + own/collaborative playlists; `--all-playlists` for followed ones) against Theorytab → `data/spotify_candidates.txt`, with playlist membership in braces, to paste from into `songs.txt`. Spotify exposes no per-playlist play counts. Full notes: [../docs/spotify.md](../docs/spotify.md). One-time setup in the docstring (a Spotify developer app with redirect `http://127.0.0.1:8888/callback`; the owner needs Premium; client id + tokens live in `~/.config/interval-trainer/spotify.json`, never in the repo).

## Run

```bash
cd code
python3 scripts/spotify_top.py --propose                       # optional: most-played Spotify tracks → Theorytab candidates
python3 scripts/fetch_theorytab.py --list scripts/songs.txt   # polite; ~2 s per section
python3 scripts/fetch_lyrics.py                                # needs: brew install yt-dlp
yt-dlp -q -f bestaudio -x --audio-format wav --postprocessor-args "ExtractAudio:-ar 22050 -ac 1" \
  -o "data/audio/%(id)s.%(ext)s" --download-archive data/audio/.archive -a <urls>   # local audio, gitignored
python3 scripts/mine_moments.py                                # first pass: the verifier reads public/clips.json for the section list
.venv/bin/python scripts/verify_clips.py                       # venv: python3.14 -m venv .venv && .venv/bin/pip install numpy librosa soundfile
python3 scripts/mine_moments.py                                # second pass: merges offsets + prominence; prints per-interval counts + timing checks
python3 -m http.server 8765 --directory public                 # then open http://localhost:8765
```

## Deploy

```bash
cd code && vercel deploy --prod
```

`vercel.json` serves `public/` as-is; `.vercelignore` keeps `data/` (1.1 GB of local audio), `.venv/` and `scripts/` out of the upload — without it a deploy ships ~800 MB. Project: `interval-trainer` on Mitchell's Vercel account. **Production URL: https://ear-trainer.mitchgordon.me** (Vercel's own URLs `interval-trainer-six.vercel.app` and `interval-trainer-mitchellgordon95s-projects.vercel.app` keep working). Since 2026-10-10 the project is connected to the private GitHub repo with Root Directory `code`, so every push to `main` deploys with the full data; the CLI deploy above is the manual fallback. `vercel.json` is included here so a fork can deploy its own copy once it has run the pipeline.
